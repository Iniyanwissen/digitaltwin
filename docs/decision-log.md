## 2026-09-25: Lightweight native-Windows infrastructure

**Decisions**
1. Develop natively on Windows in `D:\DT` (no WSL).
2. No Docker. PostgreSQL → SQLite (two files, keeping master and SaaS separate); Redis streams/state/pub-sub → in-process implementations behind the existing adapter interfaces.
3. Engine, event processor, API and pipeline trigger run in one `twin-server` process; mock-saas stays a separate process.
4. Local compute only. Snowflake/Azure (Phases 10–11) become optional.
5. uv workspace with a single lockfile; poethepoet replaces `make`.
6. Node 24 LTS instead of Node 20 (end-of-life April 2026).
7. GitHub for hosting and CI (Actions on ubuntu-latest); GitHub CLI optional.

**Reason:** the project is a proof-of-value simulation; the machine has IT restrictions on installing software; embedded components keep setup to a few user-level tools.

**Docs affected:** new `infrastructure.md`; overrides infrastructure sections of `architecture.md` and Docker/Makefile items in `implementation-plan.md`.

## 2026-09-25: Phase 2 master data decisions

**Decisions**
1. **Layouts are generated from presets, then committed as explicit YAML.** `config/layout_presets.yaml` (small/medium/large) drives `LayoutGenerator`; `python -m twin_server layout --preset medium` writes `config/layouts/building_a.yaml`, which stays the hand-editable source of truth. Desks are stored as grid blocks and expanded by the loader.
2. **Medium layout:** 1 building, 4 floors, 800 desks + 8 cabins, 43 meeting rooms + auditorium, 3 common areas (cafeteria F1, collaboration F2, lounge F3), 40 zones, 2 entrances. Floors 1-3 hot-desk, floor 4 assigned with cabins for team leads.
3. **New `config/organization.yaml`:** departments, team sizes, office days, work-pattern probabilities, employment mix and bundled name lists.
4. **SQLite table prefixes** (`master_`, `config_`, `sim_`, `ops_`) replace PostgreSQL schemas. Migrations are autogenerated from `db/tables.py` (`python -m twin_server revision -m ... --rev-id ...`).
5. **Exact mixes:** work mode, profile and employment type are apportioned exactly (largest remainder) and shuffled, so mixes match config to the nearest person instead of within random error.
6. **Team placement is deterministic:** teams go to floors and desk zones proportionally to desk capacity; no randomness involved.
7. **Auto-seed:** twin-server generates master data at startup when none exists or when any config file changed (config content hash). `poe seed --force` regenerates on demand. Health reports `master_data` as degraded if the stored version does not match config.
8. **Deterministic IDs for config/version rows:** UUIDv5 from content hashes (no uuid4 outside tests).

**Docs affected:** `infrastructure.md` (commands), `CLAUDE.md` (commands).
