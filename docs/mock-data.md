## 2. Regenerate or generate more

```bash
cd reference
pip install -r requirements.txt

python -m refsim master  --out ../mock-data/master                     # master data only
python -m refsim history --days 1  --start 2026-09-23 --out ../mock-data
python -m refsim history --days 30 --start 2026-08-24 --out ../mock-data-30d   # ~60 s, ~500 MB
python -m refsim history --preset small --days 7 --out ../mock-data-small
python -m refsim stream  --speed 60 --hours 12 > live.jsonl            # live stream as JSON lines
python -m refsim serve   --speed 60                                    # live viewer on :8765
```

- Same config + seed → identical data (except `event_id` / `simulation_run_id`, which derive from a new run UUID).
- Change `seed` or `scale_preset` in `config/simulation.yaml` for different worlds.
- Heartbeats are off in batch (`batch.emit_heartbeats`); anomalies are all 0 until Phase 9.

## 3. Data dictionary (short)

Full definitions are in `data-model.md` (tables) and `event-model.md` (events). Key columns:

| File | Key columns |
|---|---|
| `employees.csv` | employee_id, team_id, department, job_role, manager_id, home_floor_id, preferred_zone_id, employment_type, work_mode (OFFICE/HYBRID/REMOTE), behavior_profile |
| `teams.csv` | team_id, department, office_days (ISO weekdays), home_floor_id, primary_zone_id |
| `employee_work_pattern.csv` | employee_id, iso_weekday, planned_mode (OFFICE/REMOTE/FLEX) |
| `zones.csv` | zone_id, zone_type (ENTRANCE/CIRCULATION/OPEN_WORKSPACE/MEETING/CAFETERIA/COLLABORATION), x, y, width, height, is_restricted, allowed_team_ids |
| `workspaces.csv` | workspace_id, zone_id, x, y, size, status, has_sensor, device_type |
| `rooms.csv` | room_id, room_type (SMALL_MEETING/MEDIUM_MEETING/LARGE_CONFERENCE/AUDITORIUM/COMMON_AREA), area_subtype, capacity, geometry, is_bookable, has_badge_reader, has_panel |
| `access_points.csv` | access_point_id, reader_type (BUILDING_ENTRANCE/FLOOR_LOBBY/SECURE_ZONE/ROOM_DOOR), target_id, direction |
| `sensors.csv` | sensor_id, sensor_type (DESK_OCCUPANCY/ROOM_COUNT/ENVIRONMENT), target_type, target_id |

| raw events | envelope per `event-model.md` §2; `identity_class` tells you which fields may carry identity |

Coordinates are layout units on a 120 × 72 floor plan (renderer scales them).

## 4. Load it locally

**DuckDB (quick exploration):**

```sql
CREATE VIEW raw_events AS
SELECT * FROM read_json_auto('mock-data/raw/events/**/*.jsonl', hive_partitioning = true, format = 'newline_delimited');

-- arrivals per hour
SELECT substr(event_time, 12, 2) AS hour, count(*) FROM raw_events
WHERE event_type = 'ACCESS_IN' GROUP BY 1 ORDER BY 1;

-- desks logged in but vacant = held (join logins/logouts with sensor intervals) → see data-model.md FACT_WORKSPACE_SESSION
```

**PostgreSQL:** don't `\copy` CSVs into hand-written tables. Phase 2's `make seed` generates the same data through the ported generators and loads it via SQLAlchemy. The CSVs are the **expected output** used by the determinism test.

**As a test fixture:** Phase 8A's archive loader must load `mock-data/raw` unchanged; dbt tests then run against it.
